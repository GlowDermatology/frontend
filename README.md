# Glow Derma — web frontend

The Glow Derma web frontend, built from the Claude Design board "Glow Derma". It contains:

- the **storefront** in Uzbek (`/`), Russian (`/ru`) and English (`/en`) in api mode — home, catalog, categories, products, specialists, services and legal pages (see "Storefront" below); in mock mode `/`, `/ru` and `/en` keep the static **marketing landing** and the shop pages answer 404 (the storefront has no fixtures);
- the **admin panel** (`/admin`): dashboard, orders, order detail, products, product editor, categories, banners, customer card, customer groups, cashback settings, notifications, appointments, specialists (list and page: profile, photo, offered services, weekly hours, date overrides, blocked periods), services, the clinic, staff (managers only), settings (store, contacts, legal texts with publishing) and the audit log.

It runs on **mock data** behind a small data layer. That layer has the same shape as the planned Django REST Framework API, so connecting the backend replaces function bodies without touching the UI.

> **Demo mode** (`GLOWDERMA_DATA_SOURCE` unset or `mock`): admin reads come from in-memory fixtures and admin mutations are Server Actions whose mock bodies compute the next state from those fixtures without saving it. A reload restores the dataset, and every admin page shows a "Demo ma’lumotlar" marker. Nothing is sent to customers, Billz, BTS, Click/Payme or Firebase.

## Commands

Requires Node.js ≥ 20.9. The package manager is **npm** (a lockfile is committed).

```bash
npm install          # install dependencies
npm run dev          # dev server on http://localhost:3000
npm run build        # production build (Turbopack)
npm run start        # serve the production build locally (Next warns about standalone output; the image runs server.js)
npm run lint         # ESLint (flat config, next/core-web-vitals + TypeScript)
npm run typecheck    # next typegen (typed routes, PageProps) + tsc --noEmit
npm run test         # Vitest unit tests (domain rules + mock dataset invariants)
npm run format       # Prettier (with the Tailwind class sorter)
npm run check        # lint + typecheck + test + format:check
```

`npm run e2e` runs the Playwright suite in `e2e/` against a running frontend and a seeded backend (see `e2e/README.md`). CI (`.github/workflows/ci.yml`) runs `npm run check`, a mock-mode `npm run build` and a Docker image build on every pull request.

### Docker

The image is a Next.js standalone server (`output: "standalone"`), running as the unprivileged `node` user on port 3000 with a `/healthz` healthcheck.

```bash
docker build \
  --build-arg NEXT_PUBLIC_SITE_URL=https://www.glowderma.uz \
  --build-arg GLOWDERMA_ALLOWED_ORIGINS=admin.glowderma.uz \
  --build-arg GLOWDERMA_MEDIA_HOSTS=api.glowderma.uz \
  --build-arg GLOWDERMA_BUILD_SHA="$(git rev-parse --short HEAD)" \
  -t glowderma-frontend .

docker run --rm -p 3000:3000 \
  -e GLOWDERMA_DATA_SOURCE=api \
  -e GLOWDERMA_API_URL=http://api:8000 \
  -e GLOWDERMA_INTERNAL_SECRET=... \
  -e GLOWDERMA_ALLOWED_ORIGINS=admin.glowderma.uz \
  -e GLOWDERMA_COOKIE_SECURE=true \
  glowderma-frontend
```

The build refuses to run without `NEXT_PUBLIC_SITE_URL` and `GLOWDERMA_ALLOWED_ORIGINS`. The edge proxy in front must pass streamed responses through unbuffered (the app sends `X-Accel-Buffering: no` for nginx) and must allow request bodies up to 6 MB for product image uploads. The backend repository's `docs/ops/deploy.md` holds the full production compose and edge configuration.

**Deployment assumption (edge contract).** The Next server must be reachable only through a single trusted edge proxy that appends or overwrites `X-Forwarded-For` (and `X-Real-IP`). The API client forwards the rightmost `X-Forwarded-For` hop to Django as `X-GD-Client-IP` (`clientIp()` in `src/data/api/client.ts`), because that hop is the one the edge wrote from the TCP peer; hops to its left come from the browser and are ignored. If a second proxy is ever chained in front, it must collapse the header, or Django's per-client-IP throttles and `AuditEntry.ip` would see the inner proxy's address.

```

    (intl)/[locale]/           "/ru", "/en"   other landing languages (static)

    ui/                      Design-system primitives: Button, Badge, Field/TextInput/AffixInput,

  features/
    landing/                 Sections, copy dictionaries (uz/ru/en), i18n, metadata

  domain/                    Framework-free types and business rules (orders, cashback tiers,
                             products, categories, banners, jobs, appointments, notifications).
                             Unit-tested.
  data/                      The seam to the backend:
    *.ts                       server-only query dispatchers (`getOrder`, `listProducts`, …)
    *.actions.ts               Server Actions ("use server") returning ActionResult<T>
    *.schema.ts                Zod schemas shared by forms and Server Actions
    source.ts, now.ts          dataSource() (GLOWDERMA_DATA_SOURCE, per request), requestNow()
    action-guard.ts            session/csrf gate, zod field errors, api-mode refresh()
    auth.ts, auth/             staff session DAL (verifyStaff/requireStaff/getMe), cookies, jwt, csrf
    api/                       Django client (apiFetch/apiFetchRaw/cachedGet), typed catalog calls,
                               ApiError, mappers (+ recorded fixtures), generated schema
    mock/                      deterministic fixtures, *.queries.ts and *.actions.ts mock bodies
    config.ts                  client-safe constants (DEMO_NOW, referenceNow() for mock internals)
  lib/                       cn (clsx + tailwind-merge), deterministic uz formatting, fonts
```

**Rendering**

- `cacheComponents` is on, so Partial Prerendering is the default.
- The landing pages are fully static (○), with `ensureStatic` on the landing page segment.
- Admin pages prerender the shell (sidebar, header) and stream the data-dependent body inside `<Suspense>` (◐).
- The body sits inside a content-level error boundary (`ContentErrorBoundary`, `catchError` from `next/error`, in `features/admin/shell/content-error.tsx`): a board whose data or rendering fails shows "Bo‘limni yuklab bo‘lmadi" with "Qayta urinish" (`retry()`) inside `<main>`, focus moves to its heading, and the sidebar, header and mobile menu stay usable; `redirect()` / `notFound()` pass through. `src/app/admin/error.tsx` still catches failures of the shell itself.
- Components are Server Components by default. Client components are limited to interactive leaves: forms, dialogs, menus, charts, the schedule and tabs.
- List screens keep filters, sorting and pagination in the URL, so links are shareable and map 1:1 to DRF query parameters. Navigation runs in transitions, so the old rows dim instead of flashing a skeleton.

**Styling**

- Tailwind CSS 4. Design tokens are CSS variables (`--gd-*`) mapped through `@theme inline`; the board's light and dark token sets are both defined, but only light is applied.
- The default palette, type scale, radii and shadows are replaced by the design's, so off-system values stand out in review.
- Motion uses CSS only. Everything is disabled under `prefers-reduced-motion`.

## Storefront

**Routes.** Uzbek at the root with Uzbek words, Russian and English under their prefix with English words; one slug per entity in every language (`src/features/shop/routing/routes.ts` is the single source for links, the language switcher, hreflang, robots and the proxy).

| Page                                          | uz                                            | ru / en                                          |
| --------------------------------------------- | --------------------------------------------- | ------------------------------------------------ |
| Home                                          | `/`                                           | `/ru`, `/en`                                     |
| Catalog (`?q=&category=&sort=&stock=1&page=`) | `/katalog`                                    | `/{locale}/catalog`                              |
| Category                                      | `/kategoriyalar/{slug}`                       | `/{locale}/categories/{slug}`                    |
| Product                                       | `/mahsulotlar/{slug}`                         | `/{locale}/products/{slug}`                      |
| Specialists, specialist                       | `/mutaxassislar`, `/mutaxassislar/{slug}`     | `/{locale}/specialists[/{slug}]`                 |
| Services                                      | `/xizmatlar`                                  | `/{locale}/services`                             |
| Terms, privacy, booking policy                | `/shartlar`, `/maxfiylik`, `/qabul-qoidalari` | `/{locale}/terms`, `/privacy`, `/booking-policy` |
| Placeholders (noindex, replaced by W3b)       | `/savat`, `/kirish`, `/qabulga-yozilish`      | `/{locale}/cart`, `/sign-in`, `/book`            |

Numeric id URLs (`/mahsulotlar/12`, `/ru/specialists/3`) get a 301 to the slug in the proxy once the API sends slugs (backend B-W1); before that the id URL is the canonical one. Unknown slugs render the localized 404 with `noindex` (the page streams, so the status is 200 for browsers; HTML-limited crawlers get a blocking render).

**Rendering and caching.** Pages are Partial Prerendering: the header and footer are static, the body reads `storefrontEnabled()` (api mode, after `connection()`) inside Suspense and then `"use cache"` reads (`src/data/shop/catalog.ts`, profiles `catalog` 5 min and `content` 1 h, tags in `src/data/shop/tags.ts`). The reads are anonymous (`publicGet`), so one entry serves every visitor; a catalog search is a per-visitor uncached call that forwards the visitor's IP. `POST /api/revalidate` (`Authorization: Bearer $GLOWDERMA_REVALIDATE_SECRET`, body `{"entities":[{"type":"product","id":12}]}` or `{"tags":["shop:product:12"]}`) expires tags at once. The cache is per process: call every instance, or configure a shared `cacheHandlers` store.

**SEO.** Every page has a unique title and description (products: `seo_title`/`seo_description` → description → a sentence from name, volume, category and price), canonical, hreflang uz/ru/en + `x-default`, Open Graph/Twitter (product photo; generated images at `/og/home/{locale}` and `/og/category/{locale}/{slug}`), JSON-LD (Organization, MedicalClinic + Store, WebSite + SearchAction, Product + Offer in UZS with availability, BreadcrumbList, ItemList, Physician/Person, Service). `/sitemap.xml` is an index of `/sitemaps/{pages,categories,products,specialists}-{uz,ru,en}.xml` with alternates, `lastmod` from `updated_at` and images; `robots.txt` disallows `/admin`, `/api/` and every private path. `htmlLimitedBots` adds Telegram, Yandex and others so link previews and crawlers get metadata in `<head>`.

**Customer BFF** (`src/data/customer-auth/*`, `src/data/api/customer/*`). Cookies `gd_cust_access`, `gd_cust_refresh` (HttpOnly, Lax, `Path=/`, `__Secure-` on HTTPS), readable `gd_cust_csrf` and `gd_cust_in` (signed-in hint for the static header), HttpOnly `gd_dev_id` (400 days, `X-GD-Device-Id`) and `gd_dev_key` (`X-GD-Device-Key` on `auth/login/`). The proxy mints the device id and csrf only on private pages (no cookie for anonymous browsing) and bounces a lapsed private GET to `GET /api/shop/auth/refresh?next=`, which rotates through a per-process single-flight coordinator (concurrent requests share one rotation; late requests with the old token get the same new tokens within 60 s, inside the API's 120 s grace). `POST /api/shop/auth/logout` (same-origin + csrf) clears the session cookies. Request-bound calls send `X-GD-Platform: web`, the device headers, `X-GD-Client-IP` and `X-GD-Client-UA`. W3b seams: `guardCustomerAction(csrf)` and `readCustomerSession()` (`session.ts`), `runShopAction(locale, invoke)` (`features/shop/shared/action-client.ts`), `addToCart` (`features/shop/cart/cart-seam.ts`), `useCartCount` (`components/header-islands.tsx`), `apiCustomer*` modules to extend (`src/data/api/customer/auth.ts` lists the sign-in endpoints still to add).

**Local run** (api mode, seeded backend on :8001): build and start with `GLOWDERMA_DATA_SOURCE=api GLOWDERMA_API_URL=http://127.0.0.1:8001 GLOWDERMA_INTERNAL_SECRET=… GLOWDERMA_MEDIA_HOSTS=localhost:8001 GLOWDERMA_MEDIA_ALLOW_LOCAL=true` (the media variables at `next build` **and** `next start`: `next start` re-reads `next.config.ts`). `npx playwright test --project=customer-public` runs the anonymous storefront suite (no admin password needed).

## Key decisions

| Decision                                                                                                                                                   | Why                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Uzbek at `/`, Russian and English under a `[locale]` segment, one root layout per language group                                                           | Correct `<html lang>` on every page without middleware. Every landing page stays static.                                                                                                                                                                                                                                                                                                                                      |
| Data layer of async functions plus `ActionResult<T>` mutations                                                                                             | Components never import fixtures. Switching to DRF changes function bodies only, and expected failures come back as values next to the right field.                                                                                                                                                                                                                                                                           |
| Mock dataset reproduces the design exactly (pinned by tests)                                                                                               | Screenshots compare 1:1 with the board. Counts, totals and tiers stay consistent across screens.                                                                                                                                                                                                                                                                                                                              |
| Fixed demo clock (`DEMO_NOW` = Sat 24 Oct 2026 12:00, Tashkent)                                                                                            | Deterministic prerendering and no hydration mismatches. With the API, this becomes the request time.                                                                                                                                                                                                                                                                                                                          |
| Hand-written Uzbek number and date formatting                                                                                                              | `Intl` `uz` data differs between Node and browsers, which caused hydration mismatches. The board's format also needs NBSP thousands separators and U+2212 minus.                                                                                                                                                                                                                                                              |
| React Hook Form + Zod only for real forms (product editor, order cancellation, cashback adjustment, notification compose); local state for the tier editor | The tier editor validates across rows with the domain's `analyzeTiers`. Forcing that through a form library would add code without benefit.                                                                                                                                                                                                                                                                                   |
| `"use no memo"` on the four RHF form components                                                                                                            | The React Compiler memoised `register()` calls, so fields lost dirty tracking after `reset()`. Opting those components out fixes it.                                                                                                                                                                                                                                                                                          |
| Radix primitives for dialog, menu and tabs; native radios for segmented controls and selection cards                                                       | Correct keyboard and ARIA behaviour without custom focus code.                                                                                                                                                                                                                                                                                                                                                                |
| Staff social sign-in as a BFF redirect: state, PKCE (S256) and nonce sealed in one signed HttpOnly `SameSite=Lax` cookie on `Path=/admin/auth`             | Django keeps the client secrets and does the code exchange (contract §2.1); the browser never sees a token. The HMAC stops an edited or forged cookie, not a valid one planted from a sibling subdomain, so a link flow is also bound to the session that started it (the verified `sid`, checked before linking) and every state is single use per Next process (refused after a restart too; not shared between instances). |
| Unknown business behaviour is stated, not faked                                                                                                            | Features the design doesn't specify are disabled with an explanation (weekly view, "AI tahlil"); the demo says when nothing is saved (e.g. a demo OAuth link).                                                                                                                                                                                                                                                                |

## DRF integration guide

The seam is already in place: every public function in `src/data/*.ts` dispatches on `GLOWDERMA_DATA_SOURCE` (`await dataSource()`, read per request after `connection()`), so switching modes is configuration, not a code change.

1. **Switch the source.** Set `GLOWDERMA_DATA_SOURCE=api` together with `GLOWDERMA_API_URL` and `GLOWDERMA_INTERNAL_SECRET`. Each dispatcher in `src/data/<resource>.ts` has two branches: the mock branch calls `src/data/mock/<resource>.queries.ts` (the fixtures, anchored on `DEMO_NOW` / `DESIGN_DAY`), the api branch calls the endpoint named in its JSDoc through `cachedGet`/`apiFetch` (`src/data/api/client.ts`) and maps the response with `src/data/api/mappers`. Until an endpoint is wired, the api branch returns the documented empty shape via `notWiredYet()` and warns once per resource.

   | Function                                                     | Endpoint                                                                                                                                                               |
   | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | `listOrders` / `getOrderStatusCounts` (wired)                | `GET /api/v1/admin/orders/?status=&search=&fulfilment=&payment=&period=&date_from=&date_to=&customer=&ordering=&page=&page_size=`, `status-counts/`                    |
   | `getOrder` (wired, `cache()` per request)                    | `GET /api/v1/admin/orders/{id}/` (404 → `null`; `generateMetadata` and the page body share one request)                                                                |

2. **Map responses in the data layer, not in components.**
   - Convert DRF's `{count, next, previous, results}` to `Page<T>` (`mapPage`).
   - Convert snake_case to camelCase per path segment (`camelKey`, `mapFieldPath`).
   - Keep money as integer so‘m and datetimes as ISO strings with offset.
   - Domain types in `src/domain` are the contract. 404 → `null`.

3. **Mutations are Server Actions** (`src/data/*.actions.ts`, `"use server"`). Signature convention: **ids + the change + the client's idempotency `key` + the `csrf` token**, e.g. `cancelOrder(orderId, reason, key, csrf)`, `saveCashbackPolicy(draft, key, csrf)`, `sendNotification(formData, key, csrf)`; the product image calls take no key (`uploadProductImage(productId, formData, csrf)`); `saveProduct(id, values, baseline, key, csrf)` and `saveBanner(id, formData, baseline, key, csrf)` also take the values the editor loaded, so an update sends only what the admin changed. Every action:
   - calls `guardAction(csrf)` → `verifyStaff({ csrf })`, answering `{ ok: false, code: "session_expired" | "csrf" }`; the guard refuses a missing or empty token before touching the session (action arguments are attacker-controlled, the TypeScript signature does not exist at runtime);
   - re-validates its input with zod (`productFormSchema` and the per-action schemas) and returns `fieldErrors` keyed by the form's field names; the key must be a UUID;

4. **Auth.** The staff session is a BFF: tokens live in HttpOnly cookies and only the Next server calls Django. Read it inside each page's data boundary (`requireStaff()` in the `*-content.tsx` components) and in every Server Action, never in a layout. `requireStaff()` sends an expired access cookie to the refresh route and a missing session to the login page.

   **Social sign-in (contract §2.1, M0b).** `GLOWDERMA_OAUTH_PROVIDERS` enables Google and/or Facebook; the rules live in `src/data/auth/oauth.ts` (pure, unit-tested) and three route handlers:
   - `GET /admin/auth/oauth/{provider}/start?intent=login|link&next=` creates the flow — 32-byte `state`, a PKCE verifier (S256 challenge in the URL) and a `nonce` — seals it with HMAC-SHA256 (key derived from `GLOWDERMA_INTERNAL_SECRET`) into the `gd_oauth` cookie (HttpOnly, `SameSite=Lax`, `Path=/admin/auth`, 10 min, `__Secure-` + `Secure` with `GLOWDERMA_COOKIE_SECURE`) and redirects to the provider (fake mode: `/admin/auth/oauth/{provider}/fake`, which lets the tester pick the subject, the email or a failure and returns `code=fake:<subject>:<email>`; a 404 unless `GLOWDERMA_OAUTH_MODE=fake`). `next` is validated with `safeNext`; `intent=link` needs a same-origin request and a session Django accepts (`auth/me/`, renewed once through the refresh cookie — a cookie that merely exists is not enough), and the flow is sealed with that session's `sid`.
   - `GET …/callback` answers a cross-site arrival (the provider's redirect) with a same-origin bounce first, because the session cookies are `SameSite=Strict`; then it opens the cookie, compares `state` in constant time, clears the cookie, and posts `{code, code_verifier, redirect_uri, nonce}` to `auth/oauth/{provider}/` (login: the access, refresh and rotated csrf cookies are set by the same builders as the password login, then `next`) or to `…/link/` with the access token (renewed once through the refresh cookie when it lapsed during the round trip; back to Sozlamalar) — only when that token's `sid` is the one sealed into the flow, so a link flow planted into another browser is refused before Django sees the code. A state is accepted once per Next process (an in-memory set of HMAC(state) until the flow's expiry): a replayed cookie and callback URL read as an expired request, and so does a flow issued before the process started (after a restart the set is empty). Live entries are never evicted: past 100 000 live flows callbacks are refused (fail closed, one `[oauth]` warning), and `start` lets each client IP (the rightmost `X-Forwarded-For` hop, else `X-Real-IP`, as for Django) start 30 flows a minute, so one client cannot fill the set; without an edge in front (local development) there is no address and no throttle. Every refusal other than a 401 is logged (`[oauth] … refused` with status, code, field paths and request id, never the code or the verifier), so a `redirect_uri` that differs from Django's `GOOGLE_OAUTH_REDIRECT_URI` / `FACEBOOK_OAUTH_REDIRECT_URI` shows up in the Next log. Fake mode posts the nonce `*`: the backend's fake Google accepts only `nonce-<subject>` or the wildcard, it cannot see the authorize URL. Facebook takes no nonce.
   - Failures land on the login page or the account card with a signed, 5-minute `?oauth=` notice carrying the backend's Uzbek message (`social_account_not_allowed`, `oauth_exchange_failed`, `provider_unavailable`, the `link/` conflicts) or this server's own ("Kirish so‘rovi eskirgan…", "…bekor qilindi"), keeping the login's `next`; a crafted notice is ignored, and the page drops the token through the router and toasts each notice once. The account card offers "Bog‘lash" (the link flow) and "Uzish" behind a confirmation (`unlinkSocialAccount(provider, csrf)` → `DELETE auth/oauth/{provider}/`, no key, route refreshed). When the confirmation closes, focus goes to the row's action (the new "Bog‘lash" after a success), else to the row itself (a session that cannot link has no action on an unlinked row), else to the block's heading — never to the page.
   - `redirect_uri` is `<https|http>://<host>/admin/auth/oauth/{provider}/callback` with the request host only when it is in `GLOWDERMA_ALLOWED_ORIGINS` (else the first entry); register it with the provider and set Django's per-provider setting to it — `GOOGLE_OAUTH_REDIRECT_URI=https://<admin host>/admin/auth/oauth/google/callback`, `FACEBOOK_OAUTH_REDIRECT_URI=https://<admin host>/admin/auth/oauth/facebook/callback` (M2; production with `OAUTH_MODE=live` requires both, the single `OAUTH_REDIRECT_URI` is deprecated). Mock mode runs the same flow without Django: a login lands on `next`, a link returns with a demo notice.
   - Linking needs a password session (M2): Django refuses `…/link/` from a session that signed in socially with 403 `permission_denied` "Ruxsat yo‘q.", before the provider is called. Since M3 `auth/me/` says how the session signed in (`auth_method`: `password`, `google`, `facebook`, or `null` for a session opened before it was recorded), so the account card offers «Bog‘lash» only to a `password` session and otherwise shows "Ijtimoiy tarmoq orqali ochilgan sessiyada hisob bog‘lab bo‘lmaydi. Chiqing, email va parol bilan qayta kiring, so‘ng «Bog‘lash»ni bosing." (a neutral variant for `null`; `socialBlock`, `linkBlockedMessage`); «Uzish» is unchanged. A backend before M3 sends no `auth_method` at all: the mapper keeps that apart from `null` (`undefined`), and the card keeps «Bog‘lash» for it, with the 403 mapping below as the guard. A link started anyway (an old tab, a typed URL) still ends with the same text from the 403 (`oauthLinkErrorMessage`). ## Limitations and mock functionality

**Data**

- All data comes from `src/data/mock` (248 products, 1 284 orders, 432 customers, one appointment week).
- Mutations go through Server Actions whose mock bodies derive the next state from the fixtures by id and return it; the client keeps it in local state only. Because nothing is persisted, a second mutation on the same object starts again from the fixture (e.g. a status change followed by a cancellation yields the fixture's history plus the cancellation row).

**Admin access**

- In mock mode `/admin` is open (no sessions); in api mode `/admin/login` signs staff in against Django and the proxy refreshes the access cookie. `/admin` sends `noindex` headers and `robots.txt` disallows it.

**Behaviour**

- Staff social sign-in (Google, Facebook) was verified end to end in fake mode only (the BFF's fake authorize page against Django `OAUTH_MODE=fake`); the live authorize URLs are unit-tested but no real Google or Facebook client was available. Since M2 Django checks `redirect_uri` per provider (`GOOGLE_OAUTH_REDIRECT_URI`, `FACEBOOK_OAUTH_REDIRECT_URI`; locally unset, so not checked) and refuses a link from a session that signed in socially (403, shown as "sign in with the password first"). In demo mode the link flow runs but saves nothing, and the demo account has no linked provider to unlink. A state's single use is enforced per Next process (and survives a restart only by refusing older flows); with several instances behind one origin a replay can reach another instance, where only the provider's own single-use codes (live mode) guard it. Fake codes are reusable, but since M2 Django claims every `code_verifier` once in its shared Redis (an atomic `cache.add` on its hash in the login and link views), so a replay that reaches another instance gets the uniform 401 `social_account_not_allowed`; under the production settings fake OAuth answers 404 altogether. Login CSRF stays a residual risk: a valid login flow planted into a victim's browser by a sibling-subdomain cookie toss signs that browser in to the attacker's own staff account (a link flow cannot be planted, see above); the shell shows the signed-in name on every screen.
- An unknown id such as `/admin/orders/999` shows the "not found" view, but the HTTP status is 200. The body streams under Partial Prerendering. It will be 404 once data checks move before streaming or the route is made dynamic.
- The admin booking dialogs (new visit, reschedule / move, cancel) are built in the design system without a board. The time list is the 5-minute grid inside the chosen specialist's working hours of the chosen day; starts that collide with a break or a held visit are marked "band" but stay selectable, since the backend decides. In demo mode a visit created in the dialog lives only in the page's state, so it cannot be moved or cancelled afterwards (the mock actions look visits up in the fixtures).
- The header search still opens the filtered orders list (it is not a global search).
- **Gap closure (feat/m3-gaps)**: the notifications history has no search (the API offers state and kind only); the category and banner lists are filtered in the page (the API filters them by `is_active` only and they are reordered as one set, so reordering pauses while a filter is on); segments, segment members and the audit log still have no free-text search (the API has none). In demo mode a specialist or service created on the list stays on that list only (nothing is kept, so its page cannot be opened), a published terms version is not kept after a reload, and a picked photo or category image is a local preview.

- Disabled with an explanation: weekly appointment view, "AI tahlil" (phase 2).
- Sections that are not in the design, built in the design system without a board: Guruhlar (`/admin/customers/groups`, members at `/admin/customers/groups/[id]`), Sozlamalar (store settings + account card) and Harakatlar jurnali (`/admin/audit-log`) (F2b); Kategoriyalar and Bannerlar (list ordered by position, create/edit dialogs, delete confirmation, up/down reordering, CSV/XLSX export) (F2a); the customers list (F2c) and To‘lovlar (F2d). No placeholder section is left.
- Customers and cashback (F2c): the customers list (`/admin/customers`: search, status, group, ordering, 20/50 rows, export) is built in the design system without a board. The adjustment dialog checks the amount against the card's `available` before calling (the backend re-checks under its lock); the policy editor offers the next three month starts as the effective date, so `effective_from_in_past` only appears when a page is left open across a month boundary. In demo mode six generated customers without online orders are deleted (as in the seed), the mock policy save returns v4 with the backend's summary, period and warnings without persisting it, and the group dialog resolves phones against the fixtures.

- To‘lovlar (`/admin/payments`) is built in the design system without a board (filters, table, refund operations, CSV/XLSX export). In demo mode five older orders keep a refund that needs action, so every operation has a row and every `manual_reason` appears (on the refund itself, as the M3 API sends it; every demo Payme refund says `payme`): four admin-cancelled orders (Click `failed`, Click `unknown`, Payme `manual_required`, a Click `manual_required` without a Click payment id) and one expired reservation that Click captured late (`manual_required` while Click is in test mode, with its own `refund_requested` history row). - In demo mode a BTS retry answers with the created parcel at once (there is no outbox); with the API the screen polls up to 30 s and then asks for a reload.
- Order item photos render in api mode since the backend (M2) builds `image_url` from the stored media path; with a local backend `next/image` needs `GLOWDERMA_MEDIA_ALLOW_LOCAL=true`.
- Busy-order 409s and Billz's 503 on a product save cannot be produced with the fake providers from the UI; they are covered by unit tests of the actions, and the Billz one was shown through the verification proxy (see M2 sync). Since M3 the seed keeps two failed Click refunds: №10100 (its fake Click still reports the payment paid, so "Yakunlash" answers `click_not_reversed`) and №10175 (its fake Click is down: Click's 503). Others can be produced with the seeded backend, though not from the UI: set an order's `metadata.fake.click` to `{"refund": "failed", "status": "paid"}` (the fake Click rejects the refund; its status check keeps answering "paid") and cancel the order; switching `status` to `"reversed"` afterwards makes "Yakunlash" close the refund without a payout, and `"down"` makes it answer Click's 503. Removing `click_paydoc_id` from the payment's `provider_state` makes a new refund manual (`no_paydoc`) and a failed one answer the no-Click-id `conflict`. `e2e/payments.spec.ts` sets both through the backend's management shell (`e2e/backend-shell.ts`, `E2E_BACKEND_DIR`).
- Notifications (M3): the demo cancels its scheduled fixture with the backend's answers; a message scheduled in the demo lives only in the page's state, so its «Bekor qilish» answers "Topilmadi." and the row is dropped from the page (the demo never re-reads its fixtures, so the rest of the page's history stays). In api mode a 409 or 404 is re-read by the cancel Server Action in the same roundtrip. A record without `cancelled_at` (a backend before M3, which has no cancel endpoint) offers no «Bekor qilish». A cancelled campaign cannot be scheduled again (the backend has no such operation); the history shows it as "Bekor qilindi".
